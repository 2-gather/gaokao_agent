# AI 志愿规划助手

基于 Dify Workflow 与知识库的高考志愿规划辅助产品，旨在帮助考生根据高考成绩、选科、意向城市和专业方向，获取具有参考价值的院校及专业推荐。

本项目是一个 AI 产品实践项目，重点探索工作流编排、知识库检索和用户条件约束在高考志愿规划场景中的应用。

## 一、项目简介

### 项目背景

高考志愿填报涉及院校筛选、专业选择、选科要求、录取分数等多个维度。考生和家长需要从大量信息中筛选符合自身条件的院校，决策过程具有一定的信息检索和比较成本。

### 产品目标

构建一个基于用户条件和知识库数据的志愿规划辅助工具，帮助用户缩小院校筛选范围，提升信息整理与初步决策效率。

### 核心功能

- 根据高考成绩和选科条件筛选院校
- 支持意向城市和专业方向等可选条件
- 通过 Dify Workflow 组织推荐流程
- 通过知识库检索相关院校数据
- 按冲刺、稳妥、保底等层次组织推荐结果（具体层次取决于匹配结果和数据情况）

## 二、技术方案

| 模块 | 技术或方案 | 作用 |
| --- | --- | --- |
| 前端 | HTML、CSS、JavaScript | 用户输入与结果展示 |
| 后端 | Node.js、Express | 接收请求并调用工作流 API |
| AI 工作流 | Dify Workflow | 组织条件处理、知识检索与结果生成 |
| 知识库 | Dify Knowledge Base | 提供院校相关数据检索 |
| 数据文件 | TXT | 保存知识库原始数据，支持重新导入 |

项目使用工作流和知识库协同完成任务，而不是单纯将用户问题直接发送给大语言模型。

## 四、运行与复现

### 运行前准备

需要准备以下环境和资源：

- Node.js
- 可使用的 Dify 实例
- 已配置模型的 Dify 环境
- 项目提供的工作流 YAML 文件和知识库原始数据

### 1. 恢复 Dify 工作流

1. 登录自己的 Dify 实例。
2. 根据当前 Dify 版本支持的导入方式，导入 `dify/` 目录下的工作流 YAML 文件。
3. 检查模型配置、节点参数及工作流连接关系。
4. 如果知识库引用未自动恢复，重新创建并关联知识库。

### 2. 恢复知识库

1. 在 Dify 中创建新的知识库。
2. 导入 `dify/jiangsu_gaokao.txt`。
3. 等待数据处理和索引构建完成。
4. 检查工作流中的知识库检索节点，确认已关联新建的知识库。

注意：知识库原始数据与 Dify 中处理后的索引不是同一份内容。复现者需要在自己的 Dify 环境中重新创建知识库。

### 3. 配置后端

进入 `backend/` 目录，安装依赖：

```bash
npm install
```

根据 `backend/server.js` 实际使用的环境变量，在本地创建 `.env` 文件，填写自己的 Dify API 地址和 API Key。

例如：

```env
DIFY_API_URL=你的Dify工作流API地址
DIFY_API_KEY=你自己的API密钥
PORT=3000
```

以上为配置格式示例，不是可直接使用的真实凭证。请勿将包含真实密钥的 `.env` 文件上传至 GitHub。

### 4. 启动后端

在 `backend/` 目录运行：

```bash
npm start
```

启动后，根据终端输出的地址访问服务。默认端口为 `3000`，实际地址以项目运行配置为准。

如果要让前端通过后端调用工作流，请确保前端请求地址、后端接口路径和 Dify API 配置相互匹配。

## 六、复现注意事项

- 不同 Dify 实例中的模型、知识库和 API 配置可能不同，需要自行设置。
- 导入工作流后，应检查知识库关联和各节点配置。
- 知识库中的院校信息仅用于项目演示和产品验证，不应直接作为正式志愿填报依据。
- 高考录取情况受年份、招生计划、选科要求及院校政策等因素影响，实际填报应以官方最新信息为准。
- 请勿提交 API Key、密码、`.env` 文件或其他敏感信息。
